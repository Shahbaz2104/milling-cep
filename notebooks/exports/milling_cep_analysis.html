Milling condition safety monitor — reproducible analysis¶

ME-446 Artificial Intelligence & Internet of Things — Complex Engineering Problem, Fall 2026 Department of Mechanical Engineering, NED University of Engineering and Technology, Karachi.

Problem. Detect non-optimal / dangerous milling conditions (radial depth of cut RDOC = 8 mm) from accelerometer and spindle/drive-current statistics, so that an aggressive cut can be flagged before it damages the tool, spindle or workpiece. The task is binary classification; the positive (dangerous) class is the minority at 21.9 %.

Dataset. Piecuch, M. & Żabiński, T., A new open dataset from a milling process – data for classification and estimation of tool life, Scientific Data 12, 650 (2025). DOI 10.1038/s41597-025-04923-y; data DOI 10.6084/m9.figshare.28589216, CC BY 4.0. The authors' processed 120-statistic feature matrix is used; the 25 GB raw time-series archive is not redistributed here.

This notebook reproduces, in order: data loading and auditing, cleaning and target definition, exploratory analysis, leakage-safe validation design, comparison of four models, threshold selection, evaluation of the selected model, feature importance, and the unseen-case demonstration. It reads the raw files under data/raw/ and does not overwrite the saved artifacts in models/ and figures/.

Runtime: about 3–6 minutes on a laptop CPU.

1. Raw data and audit¶

The authors' CSV is a semicolon-delimited export with a UTF-8 BOM, a redundant first header row (Column1 … Column131), the real variable names on row 2, comma decimals in the metadata columns and dot decimals in the 120 sensor columns. src.data.load_raw_csv handles these quirks explicitly rather than relying on defaults.

Two independent sources are available: the feature CSV and metadata.xlsx. They are cross-checked row for row before any modelling, so a silent misalignment cannot propagate into the results.

2. Cleaning and target definition¶

Target. RDOC_class = 1 when RDOC = 8 mm (non-optimal / dangerous) and 0 when RDOC = 4.5 mm (optimal). The original paper modelled tool wear; this CEP deliberately does not reproduce that target, so the analysis is a new problem on the same public data.

Preserved rows. All 968 cycles are kept, including the single-cycle early failure and the 14 records with CycleToFailure = 0 (right-censored). Deleting difficult records would bias the class balance and break the source paper's intended use of the data. Outliers are flagged, never removed.

Excluded from the model. Identifiers, process settings, material hardness, tool metadata and remaining-life counters are excluded from the feature matrix. ToolRotation, FeedRate and ToolDiameter are constant in this campaign and cannot carry information.

Why the split strategy matters¶

RDOC and ADOC are constant within every experiment and every tool (0 experiments and 0 tools contain both classes). A random row split therefore puts cycles from the same tool in both training and test, and the model can memorise that tool's vibration/current signature instead of learning the physics of the cut. This is target leakage through grouping, not through a column.

The honest estimate must hold out whole tool groups. The notebook uses 5-fold grouped validation on tool_5fold as the primary estimate and leave-one-tool-out as a stress test. A random 5-fold score is reported by the pipeline only as a leakage control.

3. Exploratory analysis and engineering plausibility¶

The class separation should be explainable by cutting mechanics: a larger radial engagement raises the chip load, the cutting force and therefore the spindle/drive current and vibration amplitude. The strongest univariate features are checked before any model is fitted, because a classifier that works for the wrong reason is not useful evidence.

Engineering insights from the EDA¶

  1. The dangerous condition is a minority. 212 of 968 cycles (21.9 %) and 5 of 14 tools run at RDOC = 8 mm. Accuracy is a poor headline metric here; recall on the dangerous class, PR-AUC and the confusion matrix carry the engineering meaning.
  2. The design is confounded with tool identity. Because each tool has one RDOC, any random split lets a model recognise the tool. Grouped validation is mandatory for an honest number.
  3. The sensor signal is physically credible. Drive-axis mean acceleration and drive/spindle current standard deviation separate the classes with univariate AUCs of 0.89–0.94, in the direction expected from a larger radial engagement (higher force, current and vibration).
  4. Wear is a competing explanation. Dangerous tools fail sooner (mean 22.7 vs 55.8 cycles), so part of the separation may reflect wear stage rather than RDOC alone. This is treated as a limitation and probed with a remaining-life view in the dashboard.
  5. Material and tool type differ by class. The dangerous group has lower hardness and is entirely tool type 1; type 2 never appears at RDOC = 8 mm. These are plausible false-positive drivers.

4. Leakage-safe validation design¶

The feature matrix is the 120 sensor statistics only. Groups are tool identities. The primary scheme uses five grouped folds; the stress test holds out one tool at a time. Hyperparameters are tuned inside each outer fold on the training groups, so the outer estimate never sees the held-out tool during tuning.

5. Model comparison¶

Four approaches are compared, chosen to span the bias–variance and interpretability range:

Model Role Why it is appropriate
Dummy (prior) Baseline Shows what a no-skill classifier achieves on this class balance.
Logistic regression Interpretable linear model 120 correlated, heavy-tailed sensor statistics; robust scaling and a linear decision boundary give a transparent reference.
Random forest Non-linear ensemble Captures thresholds and interactions between vibration and current channels without hand-crafted features; handles 120 correlated inputs.
Histogram gradient boosting Modern boosted ensemble Strong tabular learner; included to test whether boosting beats bagging on this dataset.

All models use the same signed-log1p transform, which compresses the very large ADC counts while preserving sign. Class imbalance is handled by balanced class weights (where the library supports them) and by threshold selection, not by resampling; synthetic samples would distort the physical sensor distribution.

Metrics: ROC-AUC and PR-AUC (threshold-independent), then recall, precision, F1, specificity, MCC, balanced accuracy and Brier score at a fixed 0.5 threshold for comparison. The operating threshold is chosen afterwards on the out-of-fold probabilities.

6. Threshold selection and selected model¶

Random forest is selected on the operating-point trade-off rather than on a single ranking metric: it gives the best combination of recall, precision, MCC, balanced accuracy and Brier score after threshold tuning, and its errors are easier to explain to a process engineer than a boosted ensemble that changes more between folds. Histogram gradient boosting has the higher threshold-independent PR-AUC; this is reported honestly rather than hidden.

For a safety monitor, missing a dangerous cut (false negative) is worse than a false alarm. The threshold maximising F1 on the pooled out-of-fold probabilities is used as the pre-registered operating point; the Streamlit dashboard exposes it as a slider so the consequence of moving it can be seen directly.

9. Engineering interpretation, limitations and recommendations¶

Interpretation. The classifier is effectively a data-driven cutting-force monitor. A larger radial engagement raises the mean drive-axis acceleration and the variability of the drive/spindle current; the forest combines several correlated channels and flags the condition with 96 % recall at the tuned operating point. This is plausible from metal-cutting mechanics and does not depend on tool identity for its signal (grouped validation, leave-one-tool-out and held-out experiments all agree).

Limitations.

  • Confounded experimental design. RDOC is constant within a tool and an experiment, so RDOC, tool geometry, material batch and wear stage are entangled. Grouped validation limits the optimism but cannot fully separate these causes with this dataset.
  • Wear confound. Dangerous tools fail sooner and sensor features drift with remaining life, so some of the separation may be wear rather than RDOC. The dashboard's probability-vs-life view makes this visible.
  • Small tool count. 14 tools, 5 of them dangerous. Leave-one-tool-out is the relevant stress test, and tool 7 is a persistent false-positive source.
  • Raw signals unavailable. Models use the authors' 120 pre-computed statistics; the 25 GB raw waveforms were not available, so window length and filtering cannot be re-optimised.
  • No calibrated units. Accelerometer and current values are raw ADC counts, so thresholds are dataset-specific and would need recalibration on another machine.
  • Threshold is a policy choice. 0.44 favours recall. A plant with cheap inspection and expensive scrap may prefer a higher threshold; the dashboard exposes the trade-off.

Recommendations.

  1. Deploy as a decision-support alarm, not an automatic stop: require two consecutive flagged cycles or a rolling mean before retracting the tool.
  2. Log the probability and the top contributing features for every cycle so a process engineer can audit alarms.
  3. Re-validate on a campaign where the same tool is run at both RDOC levels; that design would break the confounding and give a genuinely causal estimate.
  4. Calibrate sensor channels to g and A before transferring the model to another machine.
  5. Re-tune the threshold per shop-floor cost ratio (missed dangerous cut vs false alarm).
